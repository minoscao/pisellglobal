## 1. 每一步做什么、留下什么

| 阶段 | 核心工作 | 产物 |
| --- | --- | --- |
| Customer Profile | 接收获客来源；建立或匹配企业、联系人、客户类型、国家、业务单元与场馆 | Customer Record；来源与负责人 |
| Follow-up | 与客户确认经营逻辑、业务模块、目标、国家/地区条件、当地要求和未知问题；明确客户意向与下一步 | Customer Brief；需求、待核实项及客户确认 |
| Solution | 取得客户图纸和现场条件；整理本地化需求；配置业务模块；制作布局、适用时的 3D 虚拟展厅、完整方案；明确标准功能、定制与排除项；形成可核对报价 | 已确认需求；图纸/布局/展示版本；Solution Pack；原系统 Quotation 引用 |
| Signed Order | 确认最终报价、软件与硬件范围、客户定制、合同及启动条件，保留实际签署依据 | Final Quote；软件与硬件清单；Approved Scope；合同/订单 |
| Handover | 根据成交版本制作交接单，说明购买目标与承诺，分出软件配置包和硬件采购包，分别交接并取得接收确认 | Handover Sheet；Software Pack → TIM；Hardware Pack → Procurement；版本及接收记录 |

客户明确意向后进入正式方案工作。初次演示或资料准备可以在前期发生，但不把一句回复自动视为愿意投入完整方案。

## 2. Solution 的内部工作链

**业务与本地条件 → 客户图纸 → 布局/配置 → 3D 展示（适用时）→ 完整方案 → 定制与交付边界 → 报价。**

- 业务与本地条件：客户目标、运营方式、业务模块、国家、语言、收款及部署条件等。未知问题列为待核实，有负责人和依据；不能依据一个国家标签自动认定所有要求已经明确。
- 图纸与现场：取得图纸、必要尺寸、设备和现场约束，记录来源及版本。本处“图”指客户空间/场地资料，不能与全球市场地图混为一谈。
- 方案与展示：用可核实的图纸形成布局，按项目需要建立 3D 虚拟展厅，再组织整体业务方案。概念生成图不是尺寸验证后的布局，不直接作为数量或价格计算依据。
- 功能与边界：逐项标明可直接使用的标准模块、所需配置、定制开发、外部依赖和不包含内容。产品/技术/交付确认后才能成为承诺。
- 报价：关联明确的模块、数量、设备、配置、定制和服务范围，以及被报价引用的图纸/方案版本。复用既有报价来源，不从一张渲染图自动推导正式金额。
- 变更：图纸、模块或范围变化需回查对方案、成本、时间和报价的影响；保留批准版本，不能静默覆盖成交依据。

这是可复用的工作组合，不要求每笔软件交易都制作完整场地 3D。需要 3D 或客户图纸时才启用相应工作包。

## 3. 三类客户的方案差异

| 客户类型 | 主要方案范围 |
| --- | --- |
| Venue Management | 场馆运营、空间/设备和场馆业务模块；目前以游乐场和娱乐中心为重点 |
| Group Solutions / Single Business | 餐饮连锁等单业态集团：相同经营模式下的多地点协同、统一标准和推广范围 |
| Group Solutions / Diversified Business | 大型品牌型跨业态集团：集团共用能力、不同业务模块、跨业态差异、深度定制与长期合作 |

三类共用客户档案和商业工作流，按项目范围配置。大型集团不会仅因深度定制或长期合作自动成为渠道伙伴。

## 4. 交接单必须解释这笔订单

交接单保留三条主线：客户为什么购买、实际购买了什么、我们承诺怎样交付。

| 内容组 | 记录内容 |
| --- | --- |
| Customer Goals | 经营目标、要解决的问题、方案选择理由、约定的成功标准 |
| Purchased Scope | 客户/场馆范围、购买模块与数量、设备和服务；关联正式合同与报价 |
| Approved Design | 客户图纸、布局、3D 展示、完整方案及各自批准版本 |
| Customisation & Exclusions | 标准范围、定制清单、外部依赖、不包含事项和未决问题 |
| Commitments & Dates | 客户沟通中形成的正式承诺、关键日期、双方条件和责任 |
| Receiving Owner | 接收团队、具体负责人、确认日期、补充资料要求 |

交接单不得只附报价金额或通用任务清单。接收方需要理解经营逻辑和订单范围；两份交接包关联同一成交版本。

### Software Pack → TIM

软件交接以**配置**为默认工作，不统称定制开发。记录购买模块、业务流程、账户/场馆范围、本地化参数、相关设计与配置要求，以及 TIM 接收确认。若合同另有经确认的定制开发，独立列出其范围和责任，不从“配置”自动扩大为开发承诺。

### Hardware Pack → Procurement

硬件交接列明型号、数量、规格、客户定制颜色、图案/印刷文件、其他批准的外观要求、交付安排及报价/订单依据。定制项关联客户确认的图案和颜色版本；未确认项标明，不推测色号或图案。采购方据此下采购单并处理采购执行，不能仅用一张效果图代替采购规格。

软件和硬件分别记录接收人、版本、未决事项与接收时间；一方接收不代表另一方也已接收。本部门准备并完成清楚交接，实际配置和采购属于接收方执行。

## 5. 对现有系统的要求

先识别现有 CM 中客户、图纸、方案、模块、报价及交接记录的实际来源，再设计引用与关联。不要因本图增加第二套报价系统、第二份客户资料或重复设计文件。

客户档案贯穿过程，每笔机会、每份方案与每份报价独立关联版本。图中的流程和界面是设计要求，并非现有 CM 功能已经通过验证。
