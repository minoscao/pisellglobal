## 核心结果

团队打开一个客户时，已经拿到三项相互对应的产物：Customer File（客户资料包）、Follow-up Plan（跟进计划）、Draft Proposal（客户专属初步提案）。来源不是一份等待人工重新调查的名单，提案也不是仅替换商家名称的模板。

同时实现两种发现方式：
- 批量寻找现有商家：按地区、行业、业务类型建立候选清单；已有客户档案先匹配，避免重复开发。
- 持续捕捉新项目：发现筹建、扩店、建设、招聘、招商、开业等公开信号，尽早建立档案并跟进。项目可能持续两至三年，未到采购时机也保留。

## 完整工作链与可交付结果

| 工作 | 实际处理 | 留下的结果 |
| --- | --- | --- |
| 设置寻找范围 | 指定国家、地区、业务类型、项目阶段与适配条件；地区可用地图圈选 | 可重复使用的搜索与监测范围 |
| 找到商家和新项目 | 搜索引擎、Google Maps、Instagram、其他社交媒体、商家官网及项目报道；按来源可用性接入 | 商家清单、新项目信号、原始页面和发现时间 |
| 确认是谁、在哪里 | 核对运营企业、集团、场馆、官网及社媒归属；识别新址与现址；交叉验证地址和地图位置 | 企业与场馆关联、核实地址、联系入口、缺项清单 |
| 整理客户资料包 | 合并重复线索，整理运营形态、项目阶段、时间、联系人、来源和历史互动 | 一份可持续更新的 Customer File |
| 准备客户专属提案 | 客户事实与获批基础素材共同输入；匹配业务问题、产品模块、案例和展示形式 | Follow-up Plan + Draft Proposal + 对应依据 |
| 推送到前台 | 生成可快速判断的客户卡片，关联完整三件套、负责人、下一步和缺项 | 同一客户集合的 Map / List / Alerts 视图 |
| 开始跟进 | 团队核查、修改、分配；选择电话、邮件、社交或拜访 | 真实联系记录、回复、时机和下一步 |
| 推进或长期培育 | 明确意向后接入 CM；时机未到继续追踪；新证据刷新资料与提案 | 商机或长期跟进档案，持续闭环 |

来源范围是设计目标，具体覆盖率、更新速度和可获取字段依赖实际接入。不能把“首次被系统发现”当成“首次公开发布”，也不能承诺所有全球信号实时捕获。每个来源显示可用情况、上次成功获取和待补项。

## 客户资料包包含什么

- **企业与关系**：商家名称、实际经营主体、所属集团、业务单元、现有场馆与新项目；一份企业主档可关联多个地点、项目和机会。
- **位置**：国家、城市、地址、地图链接与坐标、位置精度、证据来源。筹建项目可能只有城市或地块，不能自动标成精确门牌。
- **公开渠道与联系人**：官网、社交账号、公开业务联系入口、联系人职责及核实情况。无法确认的邮箱或负责人不能编成事实。
- **项目进展**：当前经营状态、筹建或扩张信号、预计时间、原文日期、事件日期、系统发现日期、最近核实日期。
- **经营需求**：已知业务模块、经营方式、本地情况、可能需求和待确认问题。观察事实与 AI 推断分开。
- **证据与历史**：原链接、相关摘录、可用图片引用、来源时间、人工备注、联系记录、提案版本、下一步。

同一个项目在多个来源出现时，合并证据并显示新变化；不重复创建客户或提醒。分店、集团总部和筹建项目也不能被错误合并成同一地点。人工修正、明确否定和已有联系历史优先保留。

## 如何做到每个客户不同

提案依据是“客户证据 × Pisell 已确认能力 × 客户所处阶段”，而不只是地区和公司名。

| 个性化部分 | 必须回答 |
| --- | --- |
| 为什么值得跟进 | 哪条具体证据与我们提供的价值相关？ |
| 为什么现在联系 | 当前项目阶段及最新变化是什么？ |
| 联系谁、怎么联系 | 哪个公开业务角色和联系渠道适合本次目的？ |
| 第一轮谈什么 | 需要验证哪些问题，哪些价值点与客户现状有关？ |
| 提供什么 | 哪些已确认模块、案例、服务组合适用，为什么？ |
| 用什么材料 | 哪些客户场景图、案例页、模块介绍及语言版本最合适？ |
| 下一步是什么 | 预约了解、演示、取得图纸，还是等待下一项目节点？ |

Approved Pisell Library 提供已批准的产品模块、能力范围、销售材料、案例、行业方案包、本地化资料及交付边界。案例与方案包仍属于 Sales Materials；引用原案例库，不建立第二套独立来源。

自动输出可以包含客户专属 PDF / PPT、初次联系草稿、会议提纲、展示概念和建议组合。开业前两年的客户与即将开业客户，应有不同的信息重点和接触节奏；现有场馆与跨业态集团，也不套用同一份需求描述。

早期 Draft Proposal 是有依据的沟通提案。图纸、预算、经营规则或现场条件未确认时，列出假设与问题，不生成虚假的确定范围、准确尺寸、可交付承诺或正式价格。图片是概念展示，不能用于推导采购数量或报价。确认需求后，进入既有 CM 的图纸、布局、适用时的 3D 虚拟展厅、完整方案和报价流程。

## 前台推送逻辑

常规推荐客户卡片关联完整三件套；卡片上直接显示为什么值得联系、最新变化、适配依据、缺项、负责人和建议下一步。名单、地图和提醒是同一批记录的不同视图，筛选、选择和跟进状态保持一致。

高时效信号可先作为“待核实提醒”出现，并继续自动补全；不能把未核实信号伪装成准备完成的客户。资料暂时取不到时，显示缺项和继续补全状态，不阻止其他已有证据进入人工判断。推送提醒不等于向客户发送内容。

通知按新证据、项目里程碑、关键回复或约定跟进日触发；同一新闻转载不反复推送。客户优先级参考适配证据、项目时机、可联系性与资料完整度，不能把单一分数当成购买意向。

## 两三年的跟进如何闭环

以同一客户及项目档案记录 Announced / Planning / Construction / Opening / Expansion 等节点。这是可配置的项目阶段示例；允许延期、取消、阶段未知及多项目并行，不强制客户沿固定日期前进。

Customer Response 后有两条去向：
- 有明确意向：转入 CM Workflow，继续需求确认、图纸、方案和原系统报价。
- 时机较晚：进入 Long-term Watch，保存下一节点及联系约定。

监测到新证据后，更新同一客户资料包，刷新相关提案内容，标出与上一版差异，再提醒负责团队。已有对话产生的问题与承诺进入下一轮跟进计划。不要把长期培育实现成每隔固定天数反复发送相同消息。

客户回复和成交/未成交原因可改善后续匹配。对案例、产品能力和正式基础素材的更改经过审核，不由客户回复直接覆盖获批资料。

## Agent 内部的工作能力

以下是拟建工具能力，不是声明已安装或上线的 Skills，也不要求用户处理技术调度。

| 能力 | 输入 | 产物 |
| --- | --- | --- |
| Search & Watch | 范围、来源、监测条件 | 商家候选与事件信号 |
| Verify & Locate | 来源页面、地图与社媒信息 | 可核查的企业、场馆、地址及联系入口 |
| Customer File | 已整理证据与原档案 | 合并更新的资料包 |
| Customer Fit | 客户事实、获批能力与适配规则 | 匹配理由、时机、问题和不适配原因 |
| Proposal Preparation | 客户资料、适配结果、获批素材 | 个性化跟进计划、提案草稿和展示材料 |
| Inbox & Watch | 准备结果、负责人、节点与新证据 | 前台卡片、差异提醒、下一步 |

资料获取、核对、匹配、整理、草稿准备和内部提醒可按设定自动完成。对外联系由团队触发，或未来在用户明确授权的对象、内容、渠道与频率范围内执行；本轮没有发送任何客户消息。

## 验证是否真正可用

1. 同一场馆从地图与 Instagram 被发现，只形成同一客户下的关联证据；不同分店保留不同地点。
2. 有筹建新闻但没有确定地址时，保留项目并显示位置缺项，不编造地图坐标。
3. 前台可从同一客户卡片打开资料、跟进建议及对应提案，追溯每个关键判断。
4. 两个经营模式或项目阶段不同的客户，模块推荐、案例、提问与下一步存在可解释的区别。
5. 时机未到的客户进入长期跟进；新增里程碑更新原档案和提案，不生成重复客户。
6. 联系前后记录与人工修正不被下一次自动更新覆盖；没有新证据时不重复提醒。
7. 早期提案不冒充已确认设计或正式报价；进入 CM 后继续使用原客户关系和引用工具。
