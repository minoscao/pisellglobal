# Venue Opportunity Alerts · 机会信号矩阵

最新补充：[运营商全流程与地区信号](OPERATOR-LIFECYCLE-SIGNALS.md)。全球新项目 Alerts 为主入口，已有场馆圈选为辅助；按运营商实际阶段确定来源，细化美国、加拿大、澳大利亚、新西兰与迪拜，不包括中国。本文的 15 类来源矩阵继续作为渠道清单。

核心对象是一份持续更新的项目档案。TikTok、Instagram、Google Maps、商场公告和审批记录，为同一项目提供不同证据。Skill 把证据对应起来，留下项目时间线、资料包和值得处理的 Alert。

本地 Skill 已建立；下表是来源分工与执行规则，并不表示所有平台已经自动接入。首批实际记录见 [Alerts](../intelligence/ALERTS.md)，唯一可维护数据源为 [资讯库](../intelligence/venue-opportunities.json)。

Google 官方说明，未来开业商家在设置日期并验证后，会于开业前 90 天显示资料。因此，Google Maps 适合定位与临近开业核对；提前一两年的发现工作应组合其他来源。这是基于该规则的工作判断，不代表每个项目都能提前找到。[Google Business Profile](https://support.google.com/business/answer/9174409?hl=en-AU)

泰国已核查的项目查询入口是 [ONEP Smart EIA Plus](https://eia.onep.go.th/site/eia)，可按项目及业主查找环境评估记录。[BMA 建筑服务](https://eservice.bangkok.go.th/) 和 [Building Control Office](https://webportal.bangkok.go.th/bco) 是建筑许可相关入口；本次没有验证到一个可任意查询全部游乐场装修许可的全国清单。审批覆盖与公开方式需逐地区核实。

商场/运营方能提供真实的分店计划，例如 Central Retail 的 [Sunday Playland 扩张公告](https://www.centralretail.com/th/newsroom/news-and-activities/1130/โรบินสันไลฟ์สไตล์-ชวนคุณหนูๆ-ปล่อยพลังแห่งจินตนาการ-รับปิดเทอมนี้ไปกับ-sunday-playland-สวนสนุกในร่มสุดพรีเมียม-ที่ครอบคลุมทั่วไทย)。但公告之后仍要继续查，不能把旧计划永久保留为“在建”。

## 锁定范围矩阵

这些是独立筛选条件，可以组合，不是强制顺序。

| 维度 | 记录内容 | 泰国首轮用法 |
| --- | --- | --- |
| Region | 国家、城市、行政区、指定区域 | Thailand；先全国发现，再按具体城市补充 |
| Place | 商场、建筑、楼层、单元、地址 | The Color Chaengwattana；没有具体租户单元时保留缺项 |
| Organisation | 开发商、商场方、运营商、集团 | Big C / BJC、Robinson Lifestyle / Central Retail、HarborLand；角色分开 |
| Venue Type | 室内儿童游乐场、其他娱乐业态 | 学校、住宅配套、室外公共游乐场不混入本次清单 |
| Project Type | 新建、扩店、搬迁、翻新 | 同一集团的分店分别建项目，保留集团关联 |
| Event | 公布、招商、审批、开工、装修、招聘、开业 | 每条来源记录它实际证明的事件 |
| Timeline | 商场完工、租户交场、场馆开业 | 每种日期独立；可有多个版本 |
| Confidence | 已确认、较可信、待核实、存在冲突 | 地点确定不代表开业时间确定 |

地点观察清单可以先有商场，之后补入租户。品牌观察清单可以先有已营业门店，之后捕捉新分店。原始企业、地点和项目相互关联，避免一条新闻生成一个重复客户。

## 交叉核对与 Alert 矩阵

| 组合证据 | 可以判断什么 | 给前台的结果 |
| --- | --- | --- |
| 单条视频，说不清地点或品牌 | 候选信号 | Needs Verification：补项目身份 |
| 商场点名租户 + 品牌点名同商场 | 已公布具体项目 | New Project：建档，附明确/未知时间 |
| 具体地点 + 有日期的装修实拍 + 项目身份对应 | 支持施工/装修阶段 | Construction Update：注明实拍依据与可信度 |
| 大楼审批 + 泛“家庭娱乐区” | 商场项目与潜在租户机会 | Needs Verification：核实儿童游乐租户 |
| 新店招聘 + 明确商场 | 筹备信号 | Milestone Update：核实开业计划 |
| 官方明确开业日 + 相同分店资料 | 有计划开业日期 | Opening Date：日期是计划，持续核对 |
| 两个来源对同一节点给出不同日期 | 时间需要核实 | Date Check：同时保留两种说法 |
| 旧 Coming Soon + 后续官方已开业 | 历史筹建期已结束 | Opened：关闭筹建提醒，保留现有客户档案 |
| 同稿转载 / 同视频重发 | 没有新事件 | 合并证据，不重复推送 |

来源数量不直接等于可信度。商场与品牌的明确原始公告可以确认“已宣布”；一张效果图不能确认“施工”。审批通过、商场完工、租户装修和场馆开业分别记录。

## 时间与资料包

每条证据保存四种时间：**原始发布、所述事件、首次发现、本次核实**。视频另存可确定的拍摄日期，不能用上传时间代替。

每个项目保存：企业与关系、地点和精度、项目阶段、场馆适配情况、时间线、原始链接、证据判断、公开业务联系入口、缺项、人工备注、负责人和下一步。泰国佛历 2569 / 2570 对应 2026 / 2027；保留原文。只有季度就显示季度，只有“Coming Soon”就显示 Date Unknown。

Alert 默认只露出：**项目｜地点｜新变化｜为什么现在跟进｜时间与确定性｜来源｜下一步**。图片或视频证据可以关联到档案中；没有取得原图，不补造“现场图”。

跟进准备根据客户事实和获批 Pisell 素材完成。早期先明确运营商、业务范围与筹备节点；不能把自动建议当成已确认需求或正式报价。来源未核实也可以推一条标明待确认的提醒。

## 复查矩阵

这是建议配置，尚未启动定时任务。

| 观察对象 | 建议频率 | 值得提醒的变化 |
| --- | --- | --- |
| 已锁定施工 / 临近开业项目 | 每日 | 品牌确认、装修节点、正式日期、延期 |
| 商场与连锁品牌观察名单 | 每周 | 新项目、租户签约、扩店 |
| 规划 / 环评 / 公开审批 | 每周，依当地更新情况调整 | 新提交、审批结果、方案变化 |
| 两三年长期项目 | 每月；出现重要新证据后提高频率 | 进入招商、动工、确定租户或采购窗口 |

新信息更新原档案；无变化不重复提醒。错过目标日期只说明需要重新核实，不能自动断言已开业或已延期。
