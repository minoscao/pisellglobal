## 1. 从哪里进入

| 导航 | 用户能做什么 |
| --- | --- |
| Overview | Dashboard / Projects / Map 三个视图切换，看项目、地区和需要处理的事 |
| Projects | 管理完整项目集合，筛选负责人、工作领域、地区和期间 |
| Partners | 按设备制造商、渠道、技术、交付服务四类查看伙伴、联系人和合作项目 |
| Customers | 按 Venue Management / Group Solutions 查看客户，以及集团、业务单元、场馆和对应方案项目 |
| Library | 查看获批市场资料及版本；引用已有案例库中的案例 |
| Performance | 查看目标、项目成果、伙伴贡献和商业结果，并进入来源明细 |

Partners 与 Customers 分为两个可见入口，适应已明确的两类工作目的；同一公司承担多重角色时仍保留一份资料。本次导航在原规范中新增 Customers，不重新设计整套导航。

Team & settings 承载成员、权限、可复用工作模板和偏好配置。Skill inbox 是跨业务共用的候选处理入口，可从全局工具或当前工作区进入，不是第五个经营领域。

## 2. 三种视图与四个业务入口

Dashboard / Projects / Map 是同一项目集合的三种呈现。切换保留地区、工作领域、负责人、期间、搜索和选择上下文。地图另可查看地区存在级别图层，Australia 已确认 Region level 1；不能将项目进度作为地区成熟度。

四个业务入口提供对应分类与关联资料：
- Brand Awareness：Activities / Channels / Marketing assets。
- Market Access：地区档案、三级存在方式、负责人和支持安排。
- Partnerships：四类伙伴与关联工作。
- Target Customers：场馆运营与跨业态集团方案两条路线。

经营分类用于找到工作，不要求一条记录先后走完四个领域。领域入口可以查看地区、企业或资料，同时进入它们关联的项目；所有实际执行工作仍汇入同一项目集合。

## 3. 每件工作如何推进

所有项目使用统一详情：Header / Tabs / Sections / Action area。展示目标、负责人、截止时间、状态、下一步；Tabs 为 Overview / Tasks / People / Files / Commercial / Activity，按工作需要显示。

任务记录动作、负责人和期限；交付物记录具体产物及审核情况；结果记录已发生的事实与证据。参展、画册、伙伴试点和集团方案只改变模板及字段，不另造详情布局。Commercial 仅在适用项目显示，资料制作无需绑定成交。

集团方案项目可同时关联多个业务单元与场馆，例如游乐场和高尔夫；共同需求和各业态差异保留在方案范围中。企业、伙伴、客户、联系人和资料通过关联复用。

## 4. Skill 如何进入日常工作

Skill inbox 提供有来源的候选、事实、缺项和建议。人可以 Shortlist / Dismiss，随后明确选择创建工作或关联已有工作。

流程：Skills 收集与准备 → 人工审阅筛选 → 人工创建或关联工作 → 人工触发具体行动 → 记录结果及下一步。Shortlist 不触发联系、预订或发布。重复收集须去重并保留人工备注。

这些业务 Skills 是计划能力；本图不表示它们已经安装、连通或运行。无候选、收集失败、权限不足、信息过期均按统一状态反馈。

## 5. 共享工具与结果

Quotation system 与 Case library 是用户已有来源工具。图中只提出引用入口，实际连接尚未核实。报价编辑、版本和金额留在原系统；案例内容留在原案例库。Marketing library 管理其他市场资料及版本，并引用案例而不复制案例库。

Cloud sales team 通过成员分工、客户跟进和项目任务支持两条客户路线，不成为新的独立销售系统。

共同商业承接保持简洁：方案与报价、签单、交付交接。Performance 展示目标、成果与收入；签约、确认收入和回款分别保留口径与来源。项目完成量和经营成果不混用，复盘结果用于下一轮目标和项目选择。

## 6. 交互与本图范围

进入任何记录都复用右侧详情，可扩为完整页；返回保留筛选和位置。候选入选不等于外部执行，按钮成功必须对应真实业务结果。窄屏收为列表和全宽详情，关键操作支持触摸与键盘。

本图是用于讨论的软件图谱，不是可运行界面，也不是所有页面、移动端和反馈状态的验收截图。后续细化依照 MASTER、页面规范和 VALIDATION。
