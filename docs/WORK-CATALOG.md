# Global Growth · 可执行工作目录

Version 3.0 · 8 Sep 2026  
用途：定义这个系统实际追踪的工作，以及 Skill、人工筛选、人工执行之间的分工。以下为第一版业务模板，不是已实施的自动化功能。

业务目标、工作组和交付物的层级以 [Operating model](OPERATING-MODEL.md) 为准。下文是可组合的执行工作模板，不能将所有行直接平铺为同一层级。v1 图片已被替代，保留作历史参考。

## 1. 系统追的是具体的事

“提升品牌”“拓展渠道”“推动增长”是工作方向，不能直接当作一条可完成的任务。

可追踪的工作应写成：参加某场展会、联系某家制造商、完成某套英文方案、给某个客户演示、谈妥某份合作条件。

核心工作标题进一步以真实执行和交付物为准：参展、制作并印刷画册、测试样机、谈妥供应条件、上线试点、发送正式报价。研究、调查、分析和写文案只是这些工作的支持任务，不能代替已参展、已交付画册、已验证样机等实际结果。

每件事必须能回答：针对谁或什么、要做什么、谁负责、什么时候做、交付什么、结果是什么、接下来做什么。

组织方式：目标指导工作主线，主线包含工作组；工作组开展项目与具体任务，任务产生交付物，项目贡献目标结果。例如 Brand Awareness / Marketing activities / Singapore Retail Expo / 交付展会物料，关联 Marketing assets 下制作的画册文件。活动、文件和目标结果不作为平级事项。

工作模板负责复用步骤。一个小事项可以只有一项任务，不要求所有事情都拆成大项目。规模更大的项目组合多个工作模板。

## 2. 人与 Skill 的工作方式

10 Sep 实施记录：已建立 `venue-opportunity-alerts` 本地 Skill，按跨来源证据更新同一项目、时间线与内部提醒。[来源与核对矩阵](OPPORTUNITY-SIGNAL-MATRIX.md) 定义来源分工，[泰国首轮资讯库](../intelligence/ALERTS.md) 区分待核实机会和已开业排除项；未开始自动定时监测或外联。

9 Sep 获客工具展开：新增 [客户发现与专属提案工具](CUSTOMER-DISCOVERY-AGENT.md)。现有商家批量寻找与新项目持续监测并行；完成客户资料包、跟进计划和初步专属提案后进入前台跟进，长期项目持续更新。自动内部准备不等于向客户发送内容。

最新补充：主动获客在 v10 暂名 Outbound Outreach（未确认命名），AI 作为支持能力，详见 AI-PROSPECTING。它可在预设授权范围内自动搜集全球开业信号、匹配账户、提醒和针对性触达；不将本节逐次人工点击示例强制套用到已授权自动流程。未授权范围或需新承诺的动作仍由负责人判断。本轮没有实际启动 Agent 或发送消息。

默认过程：**设定找什么 → Skill 收集整理 → 人工筛选 → 人工创建工作事项 → Skill 准备执行材料 → 人工触发行动 → 回收结果 → 人工确认下一步**。

| 环节 | 系统 / Skill 做什么 | 人工做什么 |
| --- | --- | --- |
| 搜集 | 按国家、行业、产品、日期等条件提取资料，保留来源 | 明确本次范围与条件，点击 Run search |
| 整理 | 去重、归类、提取联系人、标记缺项、说明匹配依据 | 核对事实，Shortlist / Dismiss / Request research |
| 立项 | 为入选对象准备模板、任务和建议交付物 | 选择级别、负责人、日期和预算，Create project |
| 准备 | 草拟联系内容、演示提纲、对比表、谈判清单等 | 审核修改，确认将要执行的具体内容 |
| 执行 | 打开已有工具，或执行已授权的具体动作 | 触发 Send / Book / Submit / Publish 等动作 |
| 回收 | 汇总跟进记录、回复、资料版本、会议结论和原系统状态 | 确认结果，安排下一步或记录停止原因 |

“选入候选”不等于“开始联系”；“同意草稿”不等于“同意签合同”；“报价已发出”不等于“报价已接受”。界面必须区分这几件事。

项目内显示本次 Skill 找到的事实、来源日期、缺项和建议。建议不能伪装成已确认结论；外部网页内容只作为资料，不作为系统指令。

## 2A. 前置工作：Marketing Readiness

最新工作归属见 DEPARTMENT-WORK-MAP。固定展厅、销售资料、案例与方案先形成可用的展示和销售准备，再持续支持市场活动、伙伴推广、跟进与方案。它不是地区支持等级 Market Access。

| 工作组 | 具体工作 | 可检查交付物 |
| --- | --- | --- |
| Showroom | 建设或更新自有固定展厅；配置可演示设备与方案；完成演示检查 | 可用展厅、演示配置、检查记录和预约安排 |
| Digital Channels | 建立或更新官网；建立社交媒体账号与主页资料；配置咨询表单、接收人和内容发布安排 | 可用网站与账号、主页内容、有效咨询入口、负责人和来源记录方式 |

这些是具体工作模板，不表示展厅或资料已经建设完成。实际客户部署与运营仍由接收团队承担；本组仅管理面向市场和销售的展示准备。第 8 节的资料任务归此层，不另建重复资料来源。

### 参展 Level 1 / Visit

去现场观察、找人和了解市场，不设置自己的展位。

| 时点 | 必须做的具体事 | 可交付结果 |
| --- | --- | --- |
| 出发前 | 确认参观日期、门票、人员、行程；筛选目标展商；制定要验证的问题；预约重点会面 | 行程、目标企业清单、会面安排、访谈提纲 |
| 现场 | 走访指定展商；记录产品、价格线索、市场反馈和联系人；区分客户与伙伴 | 企业与联系人记录、拜访备注、资料附件 |
| 结束后 | 整理并去重；挑选值得跟进的对象；分配下一步；核对费用 | 有负责人的跟进清单、市场发现、实际费用与结项记录 |

完成标准：走访结果已整理、入选对象都有下一步、实际费用已核对。不能只以“去了”判定全部工作完成。

### 参展 Level 2 / Small booth

使用小展位、联合展位或共享展台，准备有限但明确的展示方案。

| 时点 | 必须做的具体事 | 可交付结果 |
| --- | --- | --- |
| 筹备 | 确认展位和预算；选择演示产品；确定基础物料、设备、人员、运输、网络电力；预约客户 | 展位确认、演示方案、物料清单、费用与排班 |
| 开展前 | 检查设备和演示；准备线索表单；明确接待话术与客户资格判断 | 演示检查表、线索采集入口、接待分工 |
| 现场 | 演示和接待；录入企业、联系人、需求和约定事项；每日复盘 | 去重线索、演示记录、后续预约 |
| 结束后 | 归还或回收设备；对账；人工筛选线索；安排演示、伙伴会谈或报价 | 费用结算、线索接收记录、后续工作与复盘 |

### 参展 Level 3 / Full booth

独立大型展位，需要完整空间、供应商和现场执行管理。

| 工作包 | 必须做的具体事 | 可交付结果 |
| --- | --- | --- |
| 立项 | 确认目标、展位面积、预算、重点客户与负责人 | 获批范围与预算 |
| 展位设计 | 确定访客动线、设备位置、演示场景、品牌画面；审核设计 | 获批展位方案与物料规格 |
| 供应商 | 询价、比较同范围报价、确认包含项、谈交期与付款、选择搭建商 | 可比较报价、选商依据、合同与交付计划 |
| 设备与运输 | 确认设备清单、运输与必要文件、到货和返运安排 | 可追踪的设备、物流和到货验收记录 |
| 人员与销售准备 | 安排排班、培训、邀约、演示脚本、多语言资料和线索采集 | 就绪清单、排班、预约客户与演示资料 |
| 搭建验收 | 核对现场与方案、设备运行、电力网络和缺陷整改 | 验收记录与待修复事项 |
| 开展与撤展 | 接待、现场内容、每日数据、问题处理、资产回收与结算 | 线索、会议记录、设备回收与实际成本 |
| 后续转化 | 分配线索、触发联系和演示、关联伙伴或商机、复盘 | 被接收的线索、后续商机与可核对的活动结果 |

三个 Level 共用一个 Exhibition 模板。差异来自启用哪些工作包、需要哪些交付物及预算，而不是建立三个参展系统。升级级别时添加缺少的工作包并保留已完成记录，不静默重置进度。

### 谈判模板的类型

同一个 Negotiation 模板通过类型调整字段：

- **Procurement**：采购价、数量、MOQ、交期、付款、验收、保修。
- **OEM / Bundle**：软硬件组合、适配责任、授权、分成或批发价、服务边界。
- **Channel**：区域、折扣或佣金、客户归属、销售支持、续费与售后责任。

报价版本、币种、是否含税、运输与服务范围必须可对照。无法直接比较时标记缺项，不让 Skill 自动宣布“最低价就是最好”。采购供应商也不自动计入“能带来收入的渠道伙伴”。

## 6. 三类客户下的执行任务 / 云销售与客户推进

Target Customers 有三类：Venue Management（场馆运营）；Group Solutions / Single Business（餐饮连锁等单一业态、多地点集团）；Group Solutions / Diversified Business（大型品牌型跨业态集团，深度定制与长期合作）。三类共用客户接收与推进过程，方案范围依经营形态配置。完整 CM 工作包含运营逻辑、本地要求、业务模块、客户图纸、布局和适用时的 3D 虚拟展厅、定制边界、报价及交接单，见 CM-WORKFLOW。

## 11. 人工触发的 UI

保持已确认的 Pisell 视觉与共用详情，只增加任务需要的内容。

- 项目列表可显示 Work type、Level、Current phase、Next action 和负责人。
- 工作详情可调用 Research 面板；新结果进入候选清单，不直接混入正式客户或伙伴。
- 候选条目统一使用 Source / Key facts / Match reason / Missing information，以及 Shortlist / Dismiss / Request research。
- 入选后 Create project 或 Add to project，人工选择范围、Level、工作模板和负责人。
- Skill 准备好材料后显示 Review draft；可执行动作显示明确的 Send / Book / Open quote / Publish，不用一个模糊的 Run all。
- 结果录入显示 Record outcome 和 Set next action；确认后进入项目任务、历史与汇总。

候选记录单独维护 new / shortlisted / dismissed / converted。候选阶段不影响 Project 和 Task 状态，也不计入正式商机金额。

同一个候选已经立项时显示 Open project，防止重复创建。再次抓取合并新增信息，显示变化并保留人工备注与筛选结果。

## 12. 第一轮应验证的完整工作模板

1. Exhibition：同一场活动分别选 Level 1 / 2 / 3，得到正确的任务与交付物。
2. Partner development：从制造商候选到接洽、样机、联合方案、谈判、激活与首个客户。
3. Cloud sales：从候选客户到人工筛选、接收、联系、需求确认、演示、原报价与下一步。

这五条跑通后再扩展工作目录。验收必须能展示：Skill 提供的原始依据、人工选择、真实动作、可检查的交付物与清晰的下一步。
